FROM BLOCKS TO SYSTEMS

Build your own server feature

1. Choose what starts the flow

Use a command, event or timer. A command's permission field controls who can run it. Command arguments start at 1. Use a subcommand block for commands such as /coins balance.

2. Choose the player

Commands and player events provide the current player. Timers need For each online player or Run as player. For a mob death, get the event entity, then its killer, and run as that player. Missing players are skipped.

3. Remember progress

Persistent data stores numbers, text, booleans, lists and records across restarts. Player values use UUIDs; global values are shared by this plugin. Different plugins have separate data, including coins. Use records for profiles and location records for homes. Ordinary variables are temporary and shared; use saved player data for individual progress.

4. Reuse actions

Create a named Function, then call it from commands, events or buttons. Pass the target player and optional data. The Function has its own current player and input data. Use Return value when another block needs its result.

5. Build interactive menus

Place Menu button and Fill empty slots blocks inside Open menu. Each row has 9 slots, starting at 0. Put actions inside the button's click area. Clicks run for the clicking player on the next tick. Open another menu from a button to create pages. Menu items cannot be taken.

6. Add rules and rewards

Combine conditions, loops and saved data. Buy item checks saved currency and inventory space. Claim kit checks cooldowns and grants the whole list or keeps it available. Observe successful event ignores cancelled actions, making it suitable for quests. General cooldown blocks claim time before running their actions.

7. Check and start

Click a block issue to jump to it. Check validates connections and generated syntax. Save & start applies your system to the server. Export the block project to keep an editable copy. Runtime callback errors appear in the server console.
